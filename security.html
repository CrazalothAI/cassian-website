SECURITY & DOWNLOADS

A clear boundary.
A traceable build.

The site is separate from the app

The website has no native bridge, localhost connection, custom app URL handler, remote-control endpoint or automatic updater. Cassian does not receive website text, suggestions, release JSON or downloaded web scripts through this site. You choose to download and install an executable separately in Windows.

Where the installer comes from

The download page queries the public release metadata for CrazalothAI/cassian-website. The download button selects the founder-approved v8.0.0 public beta. It requires that exact prerelease tag, exactly seven files, and the pinned installer SHA-256 and size. Drafts, unrelated previews, changed bytes and unapproved release classifications are rejected. It checks the repository URL, release identity, uploaded file state, file names, version agreement, size limits and GitHub-provided SHA256 digests before enabling links. Missing, ambiguous, oversized or unexpected metadata leaves the buttons disabled.

Installer files are delivered by GitHub’s release infrastructure. The website does not accept arbitrary download destinations or uploads, and does not execute the installer. Matching source, SHA256SUMS.txt, MD5SUMS.txt and acceptance reports accompany the release. Both checksum manifests cover the final installer, portable ZIP and matching source ZIP. MD5 is for legacy comparisons only; use SHA-256 for integrity checking.

What checksums do and do not prove

A checksum identifies exact bytes and can detect a changed download when compared with a trusted reference. It is not a publisher signature or a guarantee that software is safe. The 8.0.0 public beta is unsigned at the owner's direction; trusted Windows publisher signing remains pending. Its release report retains uncompleted manual acceptance checks explicitly.

Full releases use versioned tags and matching source. Account-level immutable-release settings and protected publisher access still require their own verification; they are not advertised as already enabled.

Website protections

The public GitHub Pages site uses local scripts and artwork, a restrictive HTML content policy, bounded release responses and fixed external destinations. GitHub Pages does not apply the custom HTTP headers used in local preview; those permission/framing headers are not claimed as deployed protection. The site code never calls device APIs. It has no visitor upload service, authentication database, payment form or secrets embedded in browser code. These choices reduce exposure; they do not constitute a guarantee against every browser, hosting or supply-chain vulnerability.

Reporting a concern

For a non-sensitive issue, use the project issue tracker. Do not post secrets or exploitable private details publicly. A dedicated private vulnerability-reporting channel still needs to be established before public launch.
